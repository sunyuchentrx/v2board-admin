## 1. 安全审查

**方法**：按 6 个维度分别审查 `src/`——XSS / 注入、鉴权与会话、请求构造、敏感信息泄露、危险操作与业务逻辑、构建部署与供应链。每条候选发现由 3 个独立复核者从「能否复现 / 威胁模型 / 技术正确性」三个角度尝试推翻，至少 2 票成立才算确认。后端行为对照 V2Board 后端源码核实。

**结论**：没有 XSS、鉴权绕过这类严重漏洞；依赖 `npm audit` 为 0。共 37 条候选，确认 31 条（去重后约 20 个问题），多数为低危，其中 2 个业务 bug 影响较大。

### 需要后端配合（前端无法修，已写进代码注释）

- `AuthService::removeSession` 没有 `Cache::forget($meta['auth_data'])`，JWT 解码结果缓存 3600 秒，所以退出 / 踢下线后旧 token 最多还能用 1 小时。
- JWT 没有 `exp`，`USER_SESSIONS` 写入不带 TTL。
- `order/update` 对 `commission_status` 是无条件覆盖；要彻底避免与定时任务的竞态，需要改成按旧值做条件更新，并禁止从「已发放」改回。
- 批量生成用户只接受一个密码，整批共用；要每人独立密码需后端支持。

## 2. UI 美化方案

**目标**：现代、克制、对齐严格的 SaaS 后台风格，浅色和深色都要好看，手机上可用。

**为什么不换框架**：现有 1.1 万行页面全部基于 antd 5 + ProTable，换 shadcn / Tailwind 等于重写。「错位」的根因不在框架，而在用法（固定 px 宽度、同一行混放开关和输入框、只有部分项带 `extra` 说明、硬编码颜色），所以方案是**主题 token + 共享组件 + 逐页按规范重排**。

### 基础层（已完成）

| 位置 | 内容 |
|---|---|
| `src/theme/index.tsx` | 设计 token（主色 `#4f46e5`、圆角 8/12、控件高 34、Inter 字体配系统中文字体）；暗色模式（记住偏好，默认跟随系统）；`ConfigProvider.config({ holderRender })` 让 `Modal.confirm` / `message` 等静态方法也用上主题；antd cssVar（前缀 `--va-*`）供自定义 CSS 使用 |
| `src/styles/global.css` | 卡片、ProTable、表头、弹窗页头 / 页脚、Tabs、滚动条、等宽数字、手机端工具栏换行 |
| `src/layout/` | 侧边栏分 6 组；毛玻璃顶栏 + 面包屑；深浅色切换；用户菜单；侧边栏可折叠（记住状态）；手机端改为抽屉；页面标题和描述统一由布局渲染 |
